# 50 — UI contract

This is an abstract UI: screens, the elements on them, exact strings, and stable
**element IDs**. Each platform profile says how an element ID is exposed to
automation (web: `data-testid`; Android: Compose `testTag` exposed as resource-id).
Visual design (colors, spacing, fonts, alignment) is left to each platform. It
SHOULD follow that platform's conventions and MUST NOT change behavior.

## Screens and navigation

- **REQ-UI-001** [ui] There are exactly three screens:
  - **Login**
  - **Conversations** (home)
  - **Thread** (one conversation)

  Navigation:

  | From | Action | To |
  |---|---|---|
  | Login | valid login | Conversations |
  | Conversations | tap `conversation-row` | Thread (that peer) |
  | Conversations | `new-conversation-open` with a valid peer | Thread (that peer) |
  | Thread | `thread-back` or platform back | Conversations |
  | Conversations | `logout` | Login |

  Startup routing is REQ-ID-001.

## Elements

| Screen | Element ID | Kind | Content / behavior |
|---|---|---|---|
| Login | `login-name` | text input | Placeholder `Your name` |
| Login | `login-submit` | button | Label `Continue`. Also triggered by the keyboard "enter/done" action in `login-name`. |
| Login | `login-error` | text | Present only after a failed attempt (REQ-ID-002) |
| Conversations, Thread | `connection-status` | text | Exactly `online` or `offline` (REQ-UI-003) |
| Conversations, Thread | `queued-count` | text | Exactly `<n> queued`, e.g. `0 queued` (REQ-UI-003) |
| Conversations | `me-name` | text | The logged-in name |
| Conversations | `logout` | button | Label `Log out` |
| Conversations | `new-conversation-peer` | text input | Placeholder `Send to (name)` |
| Conversations | `new-conversation-open` | button | Label `Open` |
| Conversations | `new-conversation-error` | text | Present only after a failed attempt (REQ-UI-006) |
| Conversations | `conversation-list` | list | Contains one `conversation-row` per conversation, in REQ-ORDER-002 order |
| Conversations | `conversation-row` | list item | Contains `conversation-peer` (peer name) and `conversation-preview` (display body of the last message) |
| Conversations | `conversations-empty` | text | `No conversations yet.`, shown iff there are no conversations |
| Thread | `thread-back` | button | Label `Back` |
| Thread | `thread-peer` | text | The peer's name |
| Thread | `message-list` | list | Contains one `message-row` per message in the conversation, in REQ-ORDER-001 order |
| Thread | `message-row` | list item | Contains `message-from`, `message-body`, `message-status` and `message-time` (REQ-UI-004) |
| Thread | `thread-empty` | text | `No messages yet.`, shown iff the conversation has no messages |
| Thread | `composer-input` | text input (multi-line allowed) | Placeholder `Message` |
| Thread | `composer-send` | button | Label `Send`. Always enabled. Validation is REQ-SEND-001. |
| Thread | `composer-error` | text | Present only after a failed send attempt, until the next successful send |

Element rules:

- Element IDs are unique on screen, except list items (`conversation-row`, `message-row`) and their children, which repeat per item.
- Child IDs MUST be discoverable inside their row. Rows MUST NOT merge or hide their children from the accessibility/automation tree.

## Requirements

- **REQ-UI-002** [ui] All elements in the table exist with exactly these IDs, labels and placeholders.
- **REQ-UI-003** [ui] Both main screens show `connection-status` (the engine's connection state) and `queued-count` (current outbox length across all conversations). Both update within 500 ms of a state change.
- **REQ-UI-004** [ui] A `message-row` shows:
  - `message-from`: the sender's name.
  - `message-body`: the body, or `Unsupported message` (REQ-SYNC-004).
  - `message-status`: exactly the status value (`queued`, `sent`, `received` or `failed`).
  - `message-time`: `receivedAt`, or `createdAt` if `receivedAt` is null, in device-local time as `HH:mm` (24-hour).

  Platforms SHOULD visually distinguish my messages from the peer's (for example, alignment).
- **REQ-UI-005** [ui] Every change to the message store, outbox or connection state is reflected on screen within 500 ms, without user action.
- **REQ-UI-006** [ui] `new-conversation-open` normalizes `new-conversation-peer` with the name rule:
  - Invalid → `new-conversation-error` = `Name must be 1-32 characters: letters, digits, '_' or '-'.`
  - Equal to me → `new-conversation-error` = `You cannot message yourself.`
  - Otherwise, open the Thread for the normalized name, even if that conversation has no messages yet, and clear the input.
- **REQ-UI-007** [ui] When the Thread opens, and whenever a message is added to it, the list scrolls so that the last message is visible.
- **REQ-UI-008** [ui] After `composer-send` succeeds (REQ-SEND-003), the input is empty and keeps focus.
